# AI 제품 상담 챗봇 운영 전환 계획

최종 업데이트: 2026-09-10

## 목표

로그인 없는 홈페이지 방문자에게 QueryPie 제품에 관한 공식 근거 기반 답변만 제공한다. 근거가 부족한 제품 질문은 안전하게 답변을 보류하고 기록하며, 매일 담당자에게 전달한다. 담당자가 승인한 답변만 이후 RAG 지식으로 반영한다.

## 확정한 원칙

- 방문자 응답 경로는 현재의 경량 API + RAG 구조를 유지한다.
- Hermes Agent는 방문자 응답 경로에 넣지 않는다. 향후 미답변 분류·초안 작성 같은 내부 운영 보조에만 선택적으로 사용한다.
- 대화 기록은 현재 탭의 `sessionStorage`에만 보관한다. 서버에는 전체 대화나 IP를 저장하지 않는다.
- WebSocket은 사용하지 않는다. 질문마다 일반 HTTP API를 호출한다.
- 브라우저가 모델을 직접 호출하지 않는다. 모델 키와 정책 집행은 서버에 둔다.
- 공식 근거가 확인된 경우만 제품 답변으로 인정한다.
- 홈페이지 챗봇의 답변 범위는 [공개 제품 상담 어드바이저 정책](./ai-chat-answer-scope.md)을 따른다. 고객별 견적·구축·보안 보장·로드맵은 답변을 보류하고 문의로 연결한다.
- 챗봇이 사용자 질문으로 스스로 학습하지 않는다. 담당자가 승인한 Q&A만 지식 원천에 반영한다.
- RAG에 넣을 공식 원문 자료의 선정·제공은 사용자 담당이며, 수집 파이프라인은 제공된 자료를 입력으로 받도록 만든다.

## 완료 기준

- 제품 외 질문은 고정 안내로 종료되고 미답변 Q&A 후보에 저장되지 않는다.
- 제품 질문에 검색 근거가 없거나 모델이 근거 기반 답변을 만들지 못하면 `unanswered`로 판정된다.
- 제품 범위와 근거 부족 상태는 시스템 프롬프트에 따라 모델이 판정한다. 서버는 응답 구조와 실제 출처 ID를 검증하고 `insufficient_evidence`만 저장한다.
- 미답변 질문은 개인정보를 최소화해 영구 저장소에 중복 집계된다.
- 매일 아침 신규·반복 미답변 질문을 Slack으로 요약한다.
- 로컬 관리자 화면에서 답변을 작성·승인하고, 승인 지식을 RAG 입력 파일로 내보낼 수 있다.
- 타입 검사, 관련 테스트, 전체 테스트와 빌드가 통과한다.
