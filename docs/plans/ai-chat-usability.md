# 웹사이트 챗봇 사용성 개선 계획

작성일: 2026-10-13

상태: UI 구현·검증 완료, Hermes 답변 지침 구현 및 실제 답변 검증 진행 중. 병합·운영 배포 전.

## 요구사항과 책임

1. Markdown 표·글머리 목록·번호 목록·강조를 정상 표시한다. 요청의 `blacklist`는 기존 계획대로 `bullet list`로 해석한다.
2. 기본 답변은 짧은 문단이나 2~3개 항목으로 작성한다. 가격 단위·포함량·필수 조건·직접 요청한 상세 내용은 보존한다.
3. 상세 내용은 근거 조회 중 확인한 공식 페이지·매뉴얼 링크 1~2개로 연결한다. 링크가 없으면 답은 유지하고 URL을 만들어내거나 추가 검색을 강제하지 않는다.

회사 사이트는 표시를 담당하고 Hermes는 답변 내용·근거·표현을 담당한다. API에 답변 정책을 중복 작성하거나 UI에서 본문을 자르지 않는다.

## 작업 순서

1. 회사 사이트의 Markdown 렌더링·표 내부 스크롤·링크 중복 처리를 구현하고 검증한다.
2. Hermes Homepage의 기본 길이와 링크 정책을 수정한다. 기존 기본 소개의 URL 금지와 요청할 때만 링크 제공 규칙을 함께 정리한다.
3. 관련 문서·회귀 검사를 갱신하고 UI와 실제 답변을 검증한다.
4. 각 저장소 PR에서 변경 범위·검증·남은 문제를 확인한다.

## UI 구현 결과

- `features/ai-chat/markdown.ts`에서 기존 `markdown-it`으로 렌더링과 출처 추출을 함께 처리한다. 참조 링크·괄호·다국어 URL도 같은 방식으로 해석한다.
- `HermesAnswer`는 문단·강조·목록·표·링크를 표시한다. assistant 외부 래퍼는 블록 콘텐츠를 담을 수 있는 div이며 사용자 메시지는 일반 텍스트다.
- 임의 HTML을 실행하지 않고 HTTP(S) 링크만 허용하며 원격 이미지는 설명 텍스트로 표시한다.
- 표는 내부 가로 스크롤 영역에 들어가고 키보드로 접근·스크롤할 수 있다.
- 본문의 링크는 참고 자료에서 중복하지 않는다. 별도 참고 링크는 남긴다. 본문·참고 링크 모두 근거의 공개 URL과 언어 경로를 보존한다.
- API의 answer/sources 구조와 기존 응답 길이·보안·세션 경계는 유지한다.

## 검증과 충돌 기준

- 짧은 답변을 위해 요청한 사실·가격 단위·필수 조건을 생략하지 않는다. 상세 절차·비교·복합 질문은 충분히 답한다.
- 상세 링크는 답을 보충한다. 링크만 던져 답을 대신하거나 다른 제품·영업 제안을 추가하지 않는다.
- 답변 근거에서 공개 URL 또는 같은 사이트의 route·host를 확인한다. 내부 저장소 경로를 공개 URL처럼 쓰거나 다른 도메인의 경로를 결합하지 않는다.
- URL을 못 찾았다는 이유만으로 미확인 설명을 붙이지 않는다. 링크를 위한 무조건적인 추가 검색을 하지 않는다.
- 표는 질문에 비교가 필요할 때 사용한다. 좁은 창에서는 표 내부만 가로 스크롤한다.
