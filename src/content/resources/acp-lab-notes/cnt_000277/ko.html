서버를 등록하고 접속 권한을 정하는 것까지는 앞선 글에서 해 봤다. 이번에는 등록한 서버들을 어떻게 묶어 관리할 수 있는지 살펴봤다. 서버의 용도나 분류가 달라질 때 그룹 목록도 하나씩 고쳐야 하는지 궁금했다.

 

QueryPie의 Server Groups에는 태그 조건으로 서버를 포함하는 기능이 있다. 같은 실습 서버를 태그로 묶은 그룹과 직접 추가한 그룹에 각각 넣고, 서버 태그를 바꿨을 때 두 목록이 어떻게 달라지는지 확인했다.

 

 

서버에 분류용 태그를 붙였다

 

새 실습 서버를 EP38 Tag Membership Lab이라는 이름으로 등록했다. 서버의 태그에는 Key를 ep38-cohort, Value를 blue로 넣었다.

 

 

이번에 사용할 blue와 green은 서버를 구분하기 위해 정한 분류값이다. 이 값을 바꾸면서 같은 서버가 그룹에 포함되거나 빠지는 모습을 비교하기로 했다.

 

 

같은 서버를 두 가지 방법으로 그룹에 넣었다

 

먼저 EP38 Tagged Servers 그룹을 만들었다. Server Tags에서 Key로 ep38-cohort를 고르고, 비교 방식은 = (Equals), 값은 blue를 선택했다. 이 태그의 값이 blue인 서버를 그룹에 포함하는 조건이다.

 

설정을 저장하고 그룹을 열어 보니, 앞서 등록한 서버 한 대가 Servers 목록에 나타났다. 서버를 직접 추가하지 않았는데도 조건에 맞춰 들어와 있었다. Managed 열에는 By Server Tags라고 표시됐다.

 

 

비교할 EP38 Manual Servers 그룹도 만들었다. 이번에는 Server Tags를 비워 두고, Add Servers에서 같은 서버를 선택해 직접 추가했다.

 

 

이때는 두 그룹 모두 같은 서버 한 대를 가지고 있었다. 화면에서 보이는 서버는 같지만, 한쪽은 태그 조건으로 들어왔고 다른 쪽은 관리자가 직접 넣은 상태였다.

 

 

서버 태그만 green으로 바꿨다

 

서버 상세 화면으로 돌아가 ep38-cohort의 값을 blue에서 green으로 변경하고 저장했다. 두 그룹의 설정은 그대로 뒀다.

 

 

그룹 목록에서 EP38 Tagged Servers를 다시 열었다. Server Tags 조건은 여전히 ep38-cohort = blue였고, Servers 목록은 비어 있었다. 서버의 현재 태그가 조건과 달라지자 그룹에서 빠진 것이다.

 

 

EP38 Manual Servers도 다시 열어 봤다. 이쪽에는 같은 서버가 그대로 남아 있었다. 서버 행의 태그는 green으로 바뀌었지만, Managed는 Manual이고 서버 수는 한 대였다.

 

 

차이가 분명했다. 태그 조건으로 구성한 그룹은 현재 태그에 맞춰 목록이 달라졌고, 직접 추가한 그룹은 관리자가 지정한 서버를 유지했다.

 

 

blue로 되돌리자 그룹에 다시 나타났다

 

같은 서버의 태그 값을 다시 blue로 저장했다. EP38 Tagged Servers를 새로 열자 서버 한 대가 다시 나타났고, Managed도 By Server Tags로 표시됐다.

 

 

수동 그룹에도 서버는 계속 남아 있었고 태그 값은 blue로 표시됐다. 태그 그룹은 한 대에서 빈 목록으로, 다시 한 대로 바뀌었다. 그동안 그룹의 조건을 고치거나 서버를 직접 추가·삭제한 적은 없었다.

 

 

그룹마다 서버 목록을 고칠 필요가 없었다

 

직접 해 보니 편했던 점은 분류가 바뀔 때 손댈 곳이 명확하다는 것이었다. 그룹에는 어떤 태그를 가진 서버를 묶을지 정해 두고, 서버의 분류값을 바꾸면 됐다. 이번에는 그룹 설정을 그대로 둔 채 서버 태그만 바꿔 포함과 제외를 모두 확인했다.

 

서비스나 용도처럼 공통 기준으로 묶을 서버는 태그 조건을 활용하고, 특정 서버를 직접 지정해 관리할 때는 수동 등록을 사용할 수 있었다. QueryPie에서 서버를 등록한 뒤 목록을 유지하는 방법까지 선택할 수 있다는 점이 좋았다.

 

실습은 QueryPie Community 11.6.7과 Ubuntu 24.04.5 LTS 서버 한 대, 새 서버 그룹 두 개로 진행했다.
