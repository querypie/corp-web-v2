これまで登録と接続許可を行った。次は用途や分類の変更時に各グループ一覧も手直しする必要があるか気になった。

 

Server Groupsのタグ条件と手動追加で同じサーバーを管理し、タグ変更の結果を比較した。

 

 

分類タグを付ける

 

新実習サーバーを EP38 Tag Membership Labとして登録し、ep38-cohort=blueを付けた。

 

 

blue・greenは比較用の分類値だ。変えることで同じサーバーの加入・除外を見る。

 

 

同じサーバーを二方式でグループへ入れる

 

まず EP38 Tagged Servers を作り、Server Tagsでep38-cohort = (Equals) blueを指定した。

 

保存すると直接追加せず一覧に現れ、Managedには By Server Tagsと表示された。

 

 

比較用に EP38 Manual Servers も作り、タグ条件なしでAdd Serversから同じサーバーを追加した。

 

 

両方とも同じ1台があり、入り方だけが違う状態だった。

 

 

サーバータグだけgreenへ変える

 

サーバー詳細でep38-cohortを blueからgreenへ変更して保存した。両グループの設定は維持した。

 

 

EP38 Tagged Serversの条件はblueのままで、一覧は空になった。現在タグが条件外になったためだ。

 

 

EP38 Manual Serversには1台が残り、タグはgreen、ManagedはManualだった。

 

 

タグ構成は現値に従い、手動構成は管理者が選んだ対象を維持した。

 

 

blueへ戻すと再び含まれる

 

blueへ戻すとタググループに1台が再表示され、By Server Tagsとなった。

 

 

手動側は常に残りタグもblueになった。タグ側は1→0→1となったが、条件変更や直接追加・削除はしていない。

 

 

グループごとの一覧修正は不要だった

 

分類変更時に触る場所が明確だった。条件を決め、サーバー側を変えるだけで加入・除外を確認できた。

 

サービス・用途の共通基準ならタグ、特定対象の指定なら手動を選べた。登録後の一覧維持方法まで選べる点がよかった。

 

QueryPie Community 11.6.7、Ubuntu 24.04.5 LTS 1台、新グループ二つで実施した。
